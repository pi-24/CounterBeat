# Assets and manifests

All art, music, SFX, themes, target skins and crosshairs are declared in `data/*.json`
(`tracks`, `themes`, `targets`, `crosshairs`; each has a `version`). Gameplay code reaches them only through
`src/game/providers` (`AssetProvider`, `TrackProvider`, `ThemeProvider`; `FeedbackBus` carries gameplay events).
Rules code (`src/game/rules`, shared with the edge function) holds no asset paths; arenas only name a theme id.

**Swapping an asset is a manifest-only edit**: drop the file in `public/`, change the path in the manifest
(a replaced track should also bump `chartVersion`), and run `node tools/validate-assets.mjs`.

The validator checks schemas, required fields, licence file or `placeholder: true`, that files exist, PNG format,
and that images sit within the palette tolerance in `themes.json`. Entries with `starCost` unlock by star total.

## Palette gate

An image passes when its mean nearest-palette distance is within `palette.tolerance` (0.2, set above the measured
worst of 0.18), no more than `maxOutlierFraction` (2%) of opaque pixels are farther than `pixelTolerance` (0.25)
from every palette colour, and textures (floor/wall) are power-of-two. Indexed (colour type 3, with tRNS) PNGs are
read; 16-bit or interlaced PNGs fail with a "format:" message saying how to re-export.

## Skins and swap check

`targetSkin` in settings selects an entry of `targets.json` (PlayScreen -> TargetField). `bot-hex` and
`bot-chevron` are recoloured placeholders generated by `tools/make-target-skins.mjs`. Unknown ids fall back to
the default skin and warn once.

Manual swap check (run on 2026-11-15): pointing a track's `arena` at another theme id in `tracks.json`, a theme
`floorTexture` at another file, and a track's `audio` at another URL changed what `ThemeProvider`/`TrackProvider`
returned with no code edit (also asserted in `manifests.test.mjs`). Not exercised in a live browser from this
environment. The in-game crosshair still uses the existing HUD settings; `crosshairs.json` is ready for the
cosmetics UI.

## Deliberate duplication

`TRACKS` (bpm/bars/seed) in `rules/charts.js` duplicates `tracks.json` because rules code is shared with the edge
function and must stay free of file loading. `manifests.test.mjs` fails if they drift; chart-affecting fields are
authoritative in `charts.js`, the manifest owns paths, licences and placeholder flags.
